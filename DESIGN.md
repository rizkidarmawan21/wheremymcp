# WhereMyMCP owner workspace

Direction authorized for implementation: a utility dashboard for the single owner operating a personal MCP gateway. Reading this as: an owner control workspace for developers, in an amber and ink workshop language, dial ENERGY 2 / RHYTHM 2 / MOTION 1.

- Identity: the product name is text, with a repeated compact `MCP /` prefix in the navigation masthead. No generated logo or artwork.
- Color: warm paper `#f7f5ef`, white work surfaces, ink `#202720`, and amber `#f1ba52`. Amber identifies the primary action, not every component. Destructive actions use a dark red text and boundary plus explicit language.
- Dark theme: charcoal `#171d19` with `#202922` surfaces and warm `#f4f2e9` text. The same amber preserves the owner action hierarchy. Theme follows system preference initially and persists only the theme choice locally.
- Typography: local Avenir Next with Segoe UI and sans-serif fallbacks makes dense account and policy labels readable without a network font request. Local monospace is reserved for actual machine identifiers, JSON and generated config. Headings use the same readable family, not terminal styling.
- Layout: a compact top masthead, a directory-like navigation rail, and a dominant work area. The owner first sees gateway stop state and real recent events. Registry pages use decision-focused rows; policy pages use editable grant lists; security and backup pages use grouped forms. There are no filler charts or metric card rows.
- Spacing: an 8px rhythm joins related controls; 24px separates work groups; the main workspace has more breathing room than dense registry rows. Narrow screens use 16px workspace padding.
- Surfaces: 6px controls and 10px work panels distinguish interactive controls from content without capsule shapes. Flat borders separate work groups; only the native modal carries elevation because it blocks the background.
- Navigation: every destination maps to implemented operations in the contracts. On phones a labeled Menu button reveals the full directory; at tablet widths a shorter rail preserves room for forms. Native details expose long schema and file previews on demand.
- Status: labels describe real states, especially quarantine, disabled, revoked and stopped. Status is never conveyed by color alone.
- Overview refinement: a compact gateway policy strip precedes two work areas on wide screens. Registry inventory uses linked rows with right-aligned counts and descriptive labels. Recent activity shows six real events; identifiers and full metadata remain available in Audit events. Both work areas stack on phones.
- Navigation refinement: Workspace, Registry, Access and Operations group the existing destinations. A soft selected background distinguishes the current page. Section borders use `#d3d8cf` in light mode and `#3e4a40` in dark mode; input and button boundaries retain the stronger control border for contrast. Native buttons without an available action remain disabled.
- Motion: hover and pressed feedback only, no entrance animation or perpetual loading animation. Loading is announced in words. Reduced motion removes transitions.
- Assets and decoration: no illustrations, gradients, fake activity, invented identities or decorative status dots. Functional SVG icons retain visible tooltips and accessible action names. Exact tool fingerprints and namespace labels remain available where the owner reviews policy.
- Accessibility: visible focus, native labels and dialog focus management, 44px interactive targets, wrapping code and rows, perceivable request and error states. Both themes use AA text pairings and strong field boundaries.

- Tool access refinement: original tool names and descriptions lead each checkbox row, grouped by server. Search narrows long lists, and a fixed modal footer keeps the permission count, cancel and save available while the list scrolls. Internal gateway hashes stay in technical details. Visible profile delete controls explain required client reassignment; no client is silently assigned different access.
