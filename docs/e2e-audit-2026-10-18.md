# Dashboard repair and E2E audit

Completed locally on 2026-10-18. Verification uses disposable databases, local MCP fixtures and a separate Docker Compose project. The owner's accounts, tools, grants and credentials were not used for test mutations.

## Reproduced defects and repairs

1. Approve and Disable buttons received a null callback for unavailable server states. The shared button helper still rendered them as interactive; clicking produced `fn is not a function`. Unavailable actions now use native disabled buttons without a click handler. Browser regression checks pending, active and disabled states and exercises the supported transitions.
2. Expired owner sessions return HTTP 403 with `Owner session required`. The dashboard previously handled only HTTP 401 as an expired session, leaving subsequent actions inside an unusable workspace. It now clears the session state, closes dialogs and shows login for that specific response. Other HTTP 403 responses, including rejected password step-up, remain actionable errors.
3. Completed onboarding returns null. Passing that value to `Element.append` rendered the literal text `null` above the registry. Overview now appends the onboarding component only when it exists. The real browser workflow and container smoke test reject literal null content.
4. Backup empty-state paragraphs had excess bottom margin and the following panel had no separating gap. Empty-state paragraphs now have zero margin, compact padding and a separate bottom gap. Browser layout assertions and desktop/mobile screenshots verify the separation.
5. Newly discovered tools have an unreviewed risk value, which left the risk selector blank without making it mandatory. Submitting produced an API validation error. The selector now shows an explicit review prompt and uses native required-field validation; the owner must choose a risk before submitting.

Overview also uses linked inventory rows, grouped navigation, quieter section borders, a compact gateway state strip and a six-event activity summary. Counts and events come from the API. Audit events retains the detailed identifiers and historical account/profile metadata.

## Verification results

- `npm test`: **62 tests passed, 0 failed, 0 skipped**. This is the combined unit, integration and browser suite, not 62 separate browser E2E scenarios.
- `npm run typecheck`, `npm run build`, `node --check public/app.js` and `docker compose config --quiet`: passed.
- Docker E2E: **PASS**, project `wheremymcp-verify-e2e`, port 18080. The test project and its temporary volumes were removed afterward.
- Local owner instance: recreated with the verified image at port 8080. Served `app.js` and `styles.css` match the source bytes; readiness returned `ready`. The refresh used `--no-deps`, preserving the existing instance data and avoiding an init job competing with the running instance's maintenance lease.
- Owner password minimum remains eight characters with the existing character-class requirements.

## Remaining boundaries

Live Google/GitHub/Slack consent and external remote OAuth providers were not exercised with real credentials. Provider and OAuth failure paths use local test fixtures. Native Codex, Claude Code, Cursor, Gemini and Hermes application compatibility remains unverified beyond config generation and the official SDK transports tested.

MCP resources/prompts, the sandboxed local stdio bridge, skill publisher trust/client adapters and dashboard restore-drill tracking remain documented implementation gaps. This audit does not claim those features exist. Operating-system screen-reader review, physical mobile devices, public TLS proxy deployment and Kubernetes runtime remain outside the local checks.
